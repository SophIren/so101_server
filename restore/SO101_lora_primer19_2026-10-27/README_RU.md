# Перенос SO-101 на другой компьютер

Этот комплект относится к **этому SO-101 follower и этой камере**, с неизменёнными сборкой и креплением камеры. Архив не создавался. Рабочая среда комплекта — Linux (инструкции для Ubuntu/Debian) с udev и V4L2; перенос на Windows/macOS требует адаптации доступа к устройствам.

## Что находится в папке

- `so101_follower_calibration.json`: ID, аппаратные смещения и пределы всех шести моторов.
- `robot_setup/robot_config.json`: порт, камера, проверенные ограничения движения и защита захвата.
- `robot_setup/handeye_transform.json`: привязка камеры к роботу, программные поправки нулей модели, диапазон локальной проверки и результаты независимой проверки.
- `robot_setup/so101_kinematics.urdf`: кинематическая модель без внешних mesh-файлов.
- `camera/calibration/camera_intrinsics.json` и `.npz`: матрица камеры и искажения для **1280×720**.
- `robot_setup/audit.json`, резервные регистры и данные расчёта: проверка параметров и восстановительная информация.
- `robot_audit.py`: проверка без движения; `camera_viewer.py`: просмотр; `robot_control.py`: явно запускаемые проверочные движения; `disable_torque.py`: отключение удержания после поддержки руки.
- `robot_geometry.py`: преобразование 3D-точек камеры в систему основания, без управления моторами.
- `fit_handeye.py`, `refine_handeye.py`, `validate_handeye.py`, `calibrate_camera.py`: воспроизведение расчётов.
- `requirements.txt`, `tested_environment.json`, `SHA256SUMS`: зависимости, исходное проверенное окружение и контрольные суммы.

Координаты найденных углов и результаты проверок включены. Фотографии людей, исходные снимки и видео не копировались: для перерасчёта по сохранённым координатам углов они не нужны. Ссылки `file` в метаданных обозначают исходные кадры, не вложенные в комплект.

## 1. Скопировать папку и установить зависимости

Из этой папки:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python verify_bundle.py
sha256sum -c SHA256SUMS
```

Проверено на Python 3.12.3; исходные версии библиотек указаны отдельно. Нужна графическая сессия для окна камеры. В комплекте нет паролей, ключей или пользовательских авторизаций. Проверка контрольных сумм выполняется до изменения профиля; после редактирования соответствующие файлы закономерно перестанут совпадать.

## 2. Подключить тот же контроллер и камеру

Питание должно соответствовать используемым моторам. Рука лежит на устойчивой опоре, зона движения свободна. На новом компьютере правило udev ещё НЕ установлено, даже если оно работает на исходном компьютере.

Посмотреть устройства:

```bash
ls -l /dev/serial/by-id/ /dev/v4l/by-id/
```

Установить правило только для контроллера с серийным номером `5B8E114736`:

```bash
bash robot_setup/install_usb_access.sh
```

Это постоянное системное изменение USB-доступа; запускайте установщик только если согласны. Пароль sudo вводится исключительно в своём терминале. При необходимости переподключите USB. Ожидаемая ссылка — `/dev/so101_follower`.

Если именование камеры отличается, измените `camera.device` в `robot_setup/robot_config.json`. Для другой ссылки контроллера измените `serial_port`. Не используйте случайный номер tty/video, не проверив, что это нужное устройство.

## 3. Проверить настройки без движения

```bash
python robot_audit.py
```

Команда сверяет модель, ID, скорость, режим, смещения и пределы с сохранёнными данными; проверяет выключенное удержание. По умолчанию ничего не записывает в моторы и не включает их. Результаты сохраняются в `robot_setup/audit.json`.

В памяти **того же робота** уже записаны ID, смещения, пределы и защита захвата: перенос компьютера не требует повторного назначения ID или калибровки. Если проверка не совпала — остановитесь и выясните причину; автоматически перезаписывать регистры не следует. Резервные значения приводятся для диагностики, не для безусловного восстановления на другом роботе.

Защиту захвата можно явно применить отдельно: `python robot_audit.py --apply-gripper-protection`. Она задаёт Max_Torque_Limit=500, Protection_Current=250 и Overload_Torque=25 с проверкой записи; требует выключенного удержания. Коэффициенты P=32, I=0, D=32 на исходном роботе не перенастраивались.

## 4. Просмотр камеры

```bash
python camera_viewer.py
python camera_viewer.py --calibrated
```

Первая команда — 640×480, целевые 15 fps, без калибровки другого режима. Вторая — 1280×720 с исправлением искажений; на исходном компьютере измерено около 8,9 fps. Q или Esc закрывают окно. Одновременно запускать два захвата камеры не нужно. Калибровку 1280×720 нельзя напрямую применять к 640×480.

## 5. Проверочные движения — только явным запуском

Без флагов `python robot_control.py` печатает инструкцию и не открывает порт. Импорт этого модуля также не открывает устройства.

Небольшое движение одного сустава на 24 отсчёта (примерно 2,1°) и возврат:

```bash
python robot_control.py --execute --supported --joint wrist_flex --delta 24
```

Доступные имена: `shoulder_pan`, `shoulder_lift`, `elbow_flex`, `wrist_flex`, `wrist_roll`, `gripper`. Модуль ограничивает такой тест величиной 90 отсчётов. Значение должно помещаться в пределах сустава.

Переход в сохранённую калибровочную позу (цели 2047) и возврат:

```bash
python robot_control.py --execute --supported
```

`--supported` означает: исходная/возвратная поза имеет устойчивую механическую опору, кабели имеют запас и зона траектории свободна. Это не означает, что во время движения можно держать пальцы между звеньями. Программа сохраняет исходные энкодеры **в начале текущего запуска**, а не использует старую позу с исходного компьютера. Это проверочная последовательность, без модели окружающих препятствий и планировщика столкновений.

После успешного возврата удержание выключается. При ошибке программа останавливает цели у текущей позиции и сохраняет удержание против падения; журнал в `logs/` сообщает `HOLDING`. Поддержите плечо и предплечье, затем явно отключите удержание:

```bash
python disable_torque.py --supported
```

Не отключайте питание неподдержанной поднятой руки. Если связь пропала, физически поддержите руку перед отключением питания. Никакие команды движения или настройки на другом компьютере из этого комплекта ещё не проверялись.

## 6. Что означает точность

Внутренняя калибровка: 30 кадров, ошибка подгонки около 0,165 пикселя; три независимых ракурса — 0,20–0,60 пикселя.

Привязка камера—робот проверена на отдельной серии совместных движений: около 0,91 пикселя и 2,62 мм RMS разброса положения неподвижной доски. Это **локальная проверка согласованности**, не обещание абсолютной точности всего рабочего пространства. `robot_geometry.camera_to_base` по умолчанию не разрешает выход за проверенный диапазон суставов.

Преобразования: `T_gripper_camera` переводит точку камеры в `gripper_frame_link`; `T_base_board` описывает положение доски во время калибровочной серии. Размерности — метры. После физического перемещения доски `T_base_board` больше не описывает её новое положение. Для нового монтажа основания положение доски относительно основания тоже нельзя считать сохранённым. Привязка **камера—захват** остаётся применимой, если её механическое крепление и сам робот не изменились.

Программные поправки нулей URDF не являются аппаратными смещениями моторов. Не записывайте их в регистры сервоприводов. После смены камеры, её крепления, геометрии, аппаратных смещений или пределов нужна повторная проверка привязки. По одному пикселю монокулярной камеры нельзя получить глубину без дополнительных геометрических предположений или измерений.

## Обновление расширенной калибровки (2026-10-20)

Рабочая версия параметров: `20261020_182057`. Добавлены 46 пригодных кадров с периферии при движениях всех суставов. После удаления близких повторов — 50 ракурсов: 44 для расчёта и 6 для отложенной проверки. Модель k1/k2/k3: RMS расчёта 0,198 пикселя, отложенных ракурсов 0,386 пикселя. Четыре дополнительных контрольных ракурса: 0,209–0,242 пикселя. На полном отображении нет складывания; исправленный вид снова сохраняет широкое поле. Старое предупреждение о сильном растяжении левого края относилось к предыдущей модели.

Режим `--calibrated` использует обновлённую модель; C переключает исправленный и исходный кадры. Матрица исправленного отображения находится в `camera/calibration/rectified_view.json` относительно корня комплекта, матрица исходных пикселей — в `camera/calibration/camera_intrinsics.json`. Не смешивайте эти две системы пиксельных координат.

Привязка камера—робот пересчитана согласованно: независимая серия дала около 0,887 пикселя и 2,72 мм RMS разброса положения доски. Локальная область достоверности геометрии не расширена только из-за новых внутренних параметров камеры. Предыдущие параметры сохранены в `camera/recalibration/20261020_182057/previous_working_parameters`. Ранее приведённые численные оценки относятся к первой версии.

При повреждённых пакетах рабочая проверочная программа допускает до двух повторных запросов для чтения и идемпотентных команд движения, принимает только ответы с правильными ID, длиной и контрольной суммой. Корректный ответ с аппаратной ошибкой останавливает работу без повторов.
