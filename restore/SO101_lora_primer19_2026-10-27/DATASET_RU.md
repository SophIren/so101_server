# Запись демонстраций SO-101 с двумя камерами

Запись выполняется на компьютере, к которому подключены leader, follower и камеры.
Сервер inference для записи не нужен: вы управляете follower джойстиком, а программа
сохраняет ваши демонстрации. Новое обучение автоматически не запускается.

Используется ваш рабочий `SO101_teleop_export_2026-10-23/teleop_so101.py`:
те же калибровки, преобразование абсолютных углов, медленное выравнивание,
скорость, watchdog и ограничения усилия. В него добавлены только порты-параметры
и точки подключения записи. EEPROM, ID и смещения моторов не меняются.
Контрольные суммы экспортного комплекта обновлены для этих дополнений.

## 1. Окружение

```bash
cd /Users/m.shkut/Documents/SO101
uv pip install --system-certs --python .venv/bin/python \
  -r requirements.txt -r requirements-dataset.txt
```

Для записи не нужны PyTorch, LeRobot или GPU. PyArrow нужен для Parquet,
`imageio-ffmpeg` предоставляет FFmpeg для H.264, если системный FFmpeg отсутствует.

Закройте `run_policy.py`, другие экземпляры телеопа и просмотрщики, занимающие
те же камеры/порты. На macOS разрешите камеру вашему терминалу. Если используются
OpenCV-окна, запускайте запись из обычного локального терминала.

## 2. Камеры и подключение

Для вашей текущей перестановки индексов: **base=1, wrist=0**.

```bash
.venv/bin/python run_policy.py --probe
```

Проверьте файлы в `logs/cameras/`: base должен показывать весь стол/задачу,
wrist — область захвата. Не меняйте физическое крепление камер после сбора.
В датасете сохраняются два реальных потока, в таком порядке:

1. `observation.images.base_0_rgb` — общий вид;
2. `observation.images.left_wrist_0_rgb` — камера на руке.

Третий поток не копируется и не записывается. При обучении/запуске pi05 нужен
`policy.empty_cameras: 1` для маскированного третьего слота.

Проверка обеих рук без включения моторов и без открытия камер:

```bash
.venv/bin/python record_dataset.py --resume-holding
```

Контроллеры определяются раздельно по серийным номерам из вашего экспорта:
leader `5B79016829`, follower `5B8E114736`. Если автоопределение не сработало:

```bash
.venv/bin/python record_dataset.py --resume-holding \
  --leader-port /dev/tty.usbmodemLEADER \
  --follower-port /dev/tty.usbmodemFOLLOWER
```

Замените последние два пути фактическими. Эти же опции доступны при записи.
Одинаковый порт для двух рук запрещён. Калибровка follower для leader не используется.

## 3. Запись

Для начала выберите одну законченную задачу. Пример: взять коробку, перенести
в отмеченную область и отпустить. Используйте одну точную английскую инструкцию
для всех демонстраций этой задачи. Начальная поза, доступная область, камера и
расположение места назначения должны быть понятны из изображений.

Поддержите follower в устойчивой стартовой позе, закрепите основания, освободите
рабочую область и держите leader неподвижно при начальном выравнивании.

```bash
.venv/bin/python record_dataset.py \
  --dataset datasets/box_raw_v1 \
  --task "Pick up the box and place it in the marked area." \
  --base-camera 1 --wrist-camera 0 \
  --execute --supported --resume-holding \
  --episodes 10 --episode-seconds 45 --session-seconds 300
```

Откроются два окна камеры с индикатором `ALIGNING`, `IDLE` или `RECORDING`.
Сначала follower медленно совместится с позой leader. После `POSE ALIGNED`
и `READY` доступны клавиши (латинская раскладка, фокус терминала или окна камеры):

| Клавиша | Действие |
|---|---|
| `s` | Начать новый эпизод |
| `k` | Завершить и отметить весь эпизод успешным |
| `f` | Завершить и сохранить как неудачный, для анализа |
| `d` | Удалить текущий эпизод |
| `q` / Esc | Закончить сеанс и оставить follower в удержании |
| Ctrl+C | Прервать сеанс; незавершённый эпизод не попадёт в обучение |

После `s` выполните задачу от подхода до отпускания предмета. В конце задержитесь
на 1–2 секунды в понятном завершённом состоянии, затем нажмите `k`.
Между эпизодами, в режиме `IDLE`, верните руку в стартовую позу и переставьте
коробку. Сброс сцены не записывается в обучающий эпизод.

`--episodes 10` считает успехи только текущего сеанса. Следующий запуск той же
команды допишет ещё эпизоды в ту же папку. Уже сохранённое не перезаписывается.
Сеанс ограничен 300 секундами, включая выравнивание. По окончании повторите запуск
с `--resume-holding`. При достижении `--episode-seconds` эпизод сохраняется как
неудачный, а не автоматически объявляется успешным.

Рабочая частота вашего экспортного телеопа — **10 Гц**; она сохранена по умолчанию.
Обе камеры считываются отдельно в фоне на 30 fps, но обучающие пары записываются
по шагам управления. `--fps` можно менять в новой папке датасета; не выставляйте
30 только ради цифры, если чтение двух рук не успевает на такой частоте.
При изменении калибровок, камер, размера кадра или частоты нужна новая папка:
программа запрещает незаметно смешивать разные настройки.

Если оконный интерфейс недоступен, добавьте `--no-preview`: клавиши читаются
из интерактивного терминала, изображения всё равно записываются.

Съёмка слишком старого кадра, рассинхронизация камер, переполнение очереди записи
или ошибка диска прервут сеанс через штатное удержание телеопа. Аппаратные ошибки
и штатные защиты рабочего экспорта не игнорируются. Код не был запущен здесь
на ваших физических руках; первый новый запуск сделайте коротким.

После остановки момент остаётся включённым. Поддержите руку и предмет, завершите
процесс записи, затем при необходимости:

```bash
.venv/bin/python disable_torque.py --supported
```

## 4. Что сохраняется

```text
datasets/box_raw_v1/
  metadata.json               обе калибровки, камеры, единицы, частота, SHA256 телеопа
  sessions/*.json             логи телеопа и остановок
  episodes/episode_*/
    episode.json             задача, успех/неудача/прерывание
    samples.jsonl            полные синхронизированные записи
    base_0_rgb/*.png          исходные кадры без потерь
    left_wrist_0_rgb/*.png
```

Каждая запись содержит:

- `observation.state`: шесть измеренных положений follower в единицах модели;
- `action`: шесть **округлённых целей, действительно отправленных follower**,
  пересчитанных по его калибровке; это не сырые значения leader;
- исходные отсчёты обеих рук и отправленные цели, чтобы проверить преобразования;
- фактическое время наблюдения, команды и каждого кадра, wall time;
- нагрузку, напряжение, температуру и статус моторов, флаг предполагаемого контакта.

Порядок суставов: `shoulder_pan`, `shoulder_lift`, `elbow_flex`, `wrist_flex`,
`wrist_roll`, `gripper`. Пять суставов — RANGE_M100_100, гриппер — RANGE_0_100,
как в текущем клиенте управления. Измеренное состояние и целевое действие различаются.
Кадры для пары выбираются не позднее времени наблюдения; максимальный возраст
0.3 с, рассогласование двух камер по умолчанию не более 0.1 с.

## 5. Собрать LeRobot-датасет

Сначала закончите запись. Для первого эксперимента соберите 50–100 качественных
успехов: разные положения коробки в нужной области, умеренные вариации ориентации,
похожий старт руки. Оставьте крепления камер и калибровки стабильными.
Это ориентир для старта, не обещание определённой успешности.

```bash
.venv/bin/python prepare_dataset.py datasets/box_raw_v1 \
  --output datasets/box_lerobot_v1 \
  --repo-id marks/so101-box-v1
```

Обрабатываются только завершённые эпизоды с отметкой `success`; ошибочные,
прерванные и неудачные исключаются. `--include-failed` включает неудачные только
по явному запросу; обычно для обучения имитацией это не нужно. Короткий эпизод
(<1 с), плохие временные метки, пропущенные кадры или неверные единицы останавливают
конвертацию, а не скрываются.

Выходная папка должна быть новой. Оригиналы не удаляются. Конвертация:

- строит равномерную временную сетку, выбирая ближайшую целую пару state/action
  вместе с её изображениями; реальные времена остаются в raw и `audit/`;
- не интерполирует команды и не повышает частоту выше записанной;
- создаёт H.264-видео, начинающиеся с PTS 0, и соответствующие Parquet timestamps;
- резервирует около 10% **эпизодов целиком** для `val` (при двух эпизодах — один);
- вычисляет `meta/stats.json` только по train; сохраняет и статистики эпизодов;
- декодирует все выходные видео и проверяет их длину/размер/FPS;
- создаёт SHA256SUMS и публикует готовую папку только после успешной проверки.

Если реальная частота заметно ниже установленной, экспорт остановится и предложит
меньший `--fps`, например `--fps 8`. Не исправляйте это переименованием metadata:
у видео и таблиц должны совпадать частоты и начало времени.

Результат — LeRobot **v2.1**, который читает ваш стек VLASH через его слой
совместимости. Современный чистый LeRobot без этого слоя может потребовать v3;
для текущего обучения не конвертируйте результат в v3 самовольно.

.venv/bin/python preview_dataset.py datasets/box_lerobot_v1 --episode 0

Во втором окне видны две камеры, номер кадра, state и action. Пробел — пауза,
`q` — закрыть. Просмотрите несколько эпизодов, особенно захват и отпускание.
Обычные MP4 также лежат в `videos/chunk-000/observation.images.*/`.

`meta/train_episodes.json` и `meta/val_episodes.json` содержат точные списки.
Сгенерированная конфигурация обучения использует только train: сам по себе

Оценивать готовую политику нужно отдельными физическими пробами; низкая loss
на демонстрациях не означает успешное выполнение задачи.

## 7. Подготовить обучение для вашего сервера

Восстановленная ВМ: `m.shkut@proj.support-concept-car.mlc`. Веса:
`/opt/so101/models/so101-pi05-base`. Настройка окружения и запуска:
[server/README_RU.md](server/README_RU.md).

В примерах ниже `/opt/so101` — рабочий каталог текущей ВМ, который может пропасть
при её пересоздании. До реального обучения перенесите датасет и output_dir на
постоянный диск/в объектное хранилище; домашний NFS ограничен 8 ГБ.

Создать конфигурации для короткой проверки и основного запуска:

```bash
.venv/bin/python make_training_config.py datasets/box_lerobot_v1 \
  --output configs/box_smoke.yaml --steps 20 \
  --server-dataset /opt/so101/datasets/box_lerobot_v1 \
  --checkpoints /opt/so101/checkpoints/box_smoke_v1

.venv/bin/python make_training_config.py datasets/box_lerobot_v1 \
  --output configs/box_lora.yaml --steps 20000 \
  --server-dataset /opt/so101/datasets/box_lerobot_v1 \
  --checkpoints /opt/so101/checkpoints/box_lora_v1
```

В конфигурациях: базовый чекпоинт, два изображения + `empty_cameras=1`,
LoRA r=16/alpha=16, batch 2 с accumulation 5, bf16, явный train split.
В `policy.input_features` явно сохранены **три слота базы**, хотя в датасете
два видео. Это необходимо для прочитанной реализации `make_policy`:
если позволить ей вывести схему только из датасета, она оставит два слота,
и `prepare_images` не найдёт отсутствующий третий ключ даже при `empty_cameras=1`.
Явная схема обеспечивает маски `[True, True, False]` без записи третьего видео.
`max_delay_steps=0` соответствует нашему синхронному клиенту. При дальнейшем
переходе на асинхронное управление этот параметр согласуется отдельно.
Расширение `.yaml` содержит JSON — это допустимый синтаксис YAML.

Перенос из обычного терминала с авторизацией MLC:

```bash
ssh m.shkut@proj.support-concept-car.mlc 'mkdir -p /opt/so101/datasets /opt/so101/restore'
scp -r datasets/box_lerobot_v1 m.shkut@proj.support-concept-car.mlc:/opt/so101/datasets/
scp configs/box_smoke.yaml configs/box_lora.yaml \
  validate_dataset.py dataset_tools.py policy_client.py requirements-dataset.txt \
  configure_server_cameras.py check_training_stack.py check_adapter.py \
  m.shkut@proj.support-concept-car.mlc:/opt/so101/restore/
```

На сервере в окружении обучения (нужны зависимости `requirements-dataset.txt`,
в частности PyArrow и FFmpeg/imageio-ffmpeg):

```bash
export PATH=/opt/so101/env/bin:$PATH
export LD_LIBRARY_PATH=/opt/so101/env/lib:${LD_LIBRARY_PATH:-}
export VLASH_PALIGEMMA_PATH=/opt/so101/models/paligemma_tokenizer
cd /opt/so101/restore
python -m pip install -r requirements-dataset.txt
python validate_dataset.py /opt/so101/datasets/box_lerobot_v1 --lerobot
python check_training_stack.py box_smoke.yaml
```

`check_training_stack.py` намеренно останавливается, если установленный `vlash.train`
не сохраняет `normalize_buffers.pt` для LoRA. У оригинального VLASH это известная
проблема: адаптер без статистик нормализации может давать NaN. Для обучения
используйте training-docker или все соответствующие patched-файлы из вашего
репозитория `so101-pi05-base`, лучше в отдельном окружении/checkout от работающего
inference-сервера. Не заменяйте файлы установленного сервера вслепую.
Подробный рецепт окружения: [docs/07-lora-finetuning.md](https://github.com/jinnymo/so101-pi05-base/blob/main/docs/07-lora-finetuning.md).

После успешной проверки, в том же окружении:

```bash
vlash train box_smoke.yaml
python check_adapter.py /opt/so101/checkpoints/box_smoke_v1/checkpoints/000020/pretrained_model
```

Точное имя каталога checkpoint смотрите в выводе trainer: некоторые версии
используют другое число ведущих нулей. После проверки короткого запуска:

```bash
vlash train box_lora.yaml
```

`output_dir` для каждого запуска должен быть новым. Обучение вашей задачи
не запускалось. Перед ним остановите inference-сервер через `manage.py stop`.
Реальный новый датасет нужно отдельно проверить серверным загрузчиком.

Адаптер после обучения не является самостоятельным `model.safetensors`.
Для развёртывания нужны исходная база, адаптер и его `normalize_buffers.pt`,
загруженные вместе patched-loader'ом, либо корректный экспорт объединённой модели.
Просто указать каталог LoRA в старом `serve.py` недостаточно.

## 8. Две камеры на inference-сервере

Локальный `run_policy.py` отправляет только base и left wrist. Восстановленный
сервер использует `/opt/so101/configs/so101_pi05_server.json` с `empty_cameras: 1`.
Весовой `config.json` и три объявленных слота не изменяются; третий получает
маску false. Проверка функции `prepare_images` без загрузки весов:

```bash
/opt/so101/env/bin/python -c 'import sys; sys.path.insert(0,"/opt/so101/restore"); from configure_server_cameras import verify_images; verify_images()'
```

Ожидаются `[True, True, False]`. Проверка полного удалённого inference без оборудования
через SSH-туннель — локальный `check_remote_policy.py`; инструкции запуска и
обслуживания нового сервера находятся в [server/README_RU.md](server/README_RU.md).
Старый сервер `marks@10.16.84.22` больше не используется.
